# 首页账户展示与退出登录设计

## 目标

- 首页不再展示当前用户标识，也不在未登录状态展示“登录 / 注册”入口。
- “我的”页面继续展示用户公开标识，并新增带二次确认的退出登录操作。

## 首页调整

首页标题下方直接衔接帖子筛选器。移除 `CurrentUserBadge` 的引用；若该组件不再有其他调用，则同时删除组件及其独立测试，避免保留无效代码。

底部导航中的“我的”仍是账户系统的统一入口，本次不调整导航结构。

## 退出登录交互

“我的”页面在信用流水下方展示全宽的“退出登录”按钮，使用退出图标和低强调危险色，与账户功能入口保持视觉区分。

点击按钮后打开现有 `Drawer` 实现的底部确认面板：

- 标题：“确认退出登录？”
- 说明：“退出后将返回首页，需要重新登录才能继续使用账户功能。”
- 操作：“取消”和“确认退出”
- 提交期间确认按钮禁用并显示“退出中…”

确认操作复用现有 `signOut` 服务端 action。Supabase 会话退出成功后由该 action 重定向至首页，不新增认证接口或路由。

## 组件边界

新增一个客户端退出组件，负责打开和关闭确认面板、提交登出表单以及展示提交状态。“我的”页面继续作为服务端组件获取账户数据，仅负责渲染退出组件。

## 测试

- 首页测试断言不再出现“当前用户”及“登录 / 注册”。
- “我的”页面测试断言用户公开标识仍然显示，并存在退出登录操作。
- 退出组件测试覆盖打开确认面板、取消关闭、确认表单绑定现有 `signOut` action。
- 完成后运行相关单元测试、完整单元测试、类型检查、代码检查和构建。

## 非目标

- 不改变登录、注册、审核或会话校验流程。
- 不调整“我的”页面已有账户入口和信用流水逻辑。
- 不在首页迁移或新增其他登录入口。
