# 大厅参考稿重构设计

## 目标

以 `docs/code_artifact.html` 为视觉和交互参考，在现有 Next.js、真实帖子 API、匿名设备身份与原子领取能力之上重构大厅。大厅主体尽量一比一还原参考稿，同时保留网站名称“周三充值日拼图互助”和底部“大厅 / 发布”导航。

参考 HTML 只用于设计比对，不进入生产代码，也不纳入本次提交。

## 保留边界

- 保留 GitHub 仓库、npm 包、Vercel 项目和 Upstash 数据库使用的 `cmcc-puzzle-hub` 技术标识。
- 保留现有发布页面、帖子存储结构、设备指纹、HMAC、发布限流、领取原子性和五分钟领取回执。
- 保留口令复制、`leadeon://` 唤起、手动打开 APP 提示、白名单链接导航和双来源领取切换。
- 不使用参考 HTML 的 mock 数据、内联脚本、`alert` 或字符串拼接 DOM。

## 页面结构

大厅使用参考稿的移动端纵向结构：

1. 420px 最大宽度的白色内容区位于浅灰页面背景中。
2. 吸顶头部依次包含网站名称、折扣分段控件、类型分段控件、拼图盘提示和拼图盘。
3. 列表区包含“最新发布”、刷新按钮、当前已加载数量、帖子卡片、分页按钮及各类状态。
4. 页面底部保留现有固定导航。

网站标题继续显示“周三充值日拼图互助”，不使用参考稿中的“拼图大厅”。大厅内容保持 20px 水平间距，标题为 22px 粗体；颜色、阴影、边框和控件间距按参考稿映射到现有 Tailwind 设计体系。

## 筛选状态

大厅默认筛选为：

- 折扣：8 折
- 类型：全部分类
- 拼图编号：未选择

筛选状态写入 URL 查询参数：

- `discount=95|90|80`
- `type=GIVE|REQUEST`
- `pieceNumber=<正整数>`

不选择类型或拼图编号时省略对应参数。初次访问没有 `discount` 时按 8 折渲染；用户选择其他值后通过 `router.replace` 更新 URL。每次更新删除旧游标参数。

切换折扣时清除 `pieceNumber`。点击拼图块选择编号，再次点击同一块取消选择。刷新、前进后退和分享 URL 后，界面可从查询参数恢复。

## 分段控件和拼图盘

折扣控件包含：

- `95折(4块)`
- `9折(6块)`
- `8折(9块)`

类型控件包含：

- `全部分类`
- `只看赠送`
- `只看求助`

控件使用语义化按钮并暴露选中状态，不使用不可访问的 `div` 点击事件。

拼图盘使用可聚焦的按钮网格实现，不使用 Canvas。视觉保持参考稿的 270px 方形盘面、浅灰边框、数字居中和蓝色选中态，同时支持键盘操作：

- 95 折：2 列 × 2 行
- 9 折：2 列 × 3 行
- 8 折：3 列 × 3 行

提示文案随折扣显示“四宫格”“六宫格”或“九宫格”。在窄屏上盘面最大宽度受容器约束，但保持正方形和稳定网格，不产生横向滚动。

## API 和仓储筛选

`GET /api/posts` 新增可选 `pieceNumber` 参数。解析规则：

1. 必须是十进制正整数，不能包含空格、小数、符号或重复参数。
2. 若同时存在折扣，编号必须在该折扣范围内：95 折 1-4、9 折 1-6、8 折 1-9。
3. 若没有折扣，以所有档位最大编号 9 作为上限。
4. 非法输入返回 `400 INVALID_INPUT`，错误字段为 `pieceNumber`。

仓储过滤发生在读取 Redis 帖子后、收集分页结果前。只有 `pieceNumber` 匹配的记录进入当前页；仓储继续批量扫描索引，直至收集到 `limit + 1` 条匹配记录或索引耗尽。这样拼图编号筛选覆盖完整索引，不会只筛选浏览器当前加载的帖子，游标仍按发布时间和帖子 ID 稳定排序。

## 列表和刷新

列表区由 `PostFeed` 继续负责真实请求、取消旧请求、分页、领取后移除和错误恢复。

列表头包含：

- “最新发布”
- 带 `RefreshCw` 图标的刷新按钮
- `共 N 条`，其中 N 是当前已加载并仍可见的帖子数

刷新按钮重新加载第一页。请求期间禁用重复刷新、旋转图标并展示参考稿的加载状态；筛选变化同样取消旧请求并重置页面。存在下一页时保留“加载更多”，加载后数量随已加载记录增加。

状态映射：

- 首次加载：居中旋转指示和“正在寻找最新的拼图...”
- 空状态：拼图图标和“当前条件下暂无数据，试试其他拼图吧”
- 请求失败：错误文案和“重试”按钮，筛选状态不丢失
- 加载更多：按钮内显示加载状态，不清空现有帖子

## 帖子卡片

帖子卡片采用参考稿的紧凑横排：

- 左侧第一行显示类型标签和“折扣 · 第 N 号”
- 赠送标签使用浅蓝底蓝字，求助标签使用浅橙底橙字
- 第二行显示来源能力和相对发布时间
- 双来源显示“口令 + 链接”，单来源显示“仅有口令”或“仅有链接”
- 右侧固定为蓝色“一键获取”按钮

相对时间由 `createdAt` 在客户端计算，至少覆盖“刚刚”“N 分钟前”“N 小时前”，更早内容显示本地日期。卡片仍通过 `ClaimDrawer` 发起真实领取；领取成功并关闭抽屉后，从当前列表移除帖子。

## 领取抽屉

领取抽屉按参考稿调整顶部圆角、遮罩、标题、关闭按钮和操作按钮层级，但不改变领取协议。

- 标题根据帖子类型显示“领取 … 拼图”或“助力 … 拼图”。
- 双来源时，链接为蓝色主操作，口令为灰色次操作。
- 只有单一来源时，该来源使用蓝色主操作。
- 设备身份加载、身份失败重试、API 错误、口令复制失败、复制成功后的手动打开提示和再次唤起按钮继续保留。
- 首次成功响应继续缓存在抽屉内存中，切换领取方式不重复请求领取 API。

## 组件边界

- `src/app/page.tsx`：解析并校验页面查询参数，组合大厅布局。
- 大厅筛选组件：渲染两组分段控件、提示和拼图盘，负责 URL 更新。
- `PostFeed`：接收 `type`、`discount`、`pieceNumber`，负责加载、刷新、分页、计数及状态。
- `PostCard`：负责参考稿卡片视觉、来源文案和相对时间。
- `ClaimDrawer`：保留领取状态机，只调整参考稿视觉和主次操作顺序。
- API 路由和帖子仓储：校验并执行完整数据集上的编号筛选。

不新增全局状态库。筛选以 URL 为唯一共享状态，领取状态继续局部保存在卡片与抽屉中。

## 测试和验收

自动化测试覆盖：

1. URL 筛选状态、默认 8 折、类型切换、编号切换和折扣切换清空编号。
2. 95 折 2×2、9 折 2×3、8 折 3×3 的拼图盘及选中语义。
3. API 的 `pieceNumber` 合法值、越界、非整数、重复参数和折扣组合校验。
4. 仓储跨批次收集编号匹配记录、分页游标和无结果情况。
5. 列表刷新、取消旧请求、数量、加载、空状态、错误和加载更多。
6. 卡片标签、来源能力、相对时间、“一键获取”和领取后移除。
7. 现有口令、链接及双来源领取测试继续通过。
8. lint、类型检查、单元测试、生产构建和 Playwright E2E 全部通过。

视觉验收使用 Playwright 在 320×568、375×812、430×932 和桌面视口截图，对比参考 HTML 与实际大厅。重点检查吸顶头部、盘面比例、卡片密度、抽屉、底部导航、文字换行和横向溢出；不得出现控件重叠、文字截断或空白画面。
