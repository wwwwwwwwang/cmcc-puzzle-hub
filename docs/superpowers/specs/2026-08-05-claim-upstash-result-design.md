# 领取接口 Upstash 返回值兼容设计

## 问题

领取 Lua 脚本返回 JSON 字符串。`@upstash/redis` 默认开启自动反序列化，线上执行 `EVAL` 后会把该 JSON 转换为 JavaScript 对象；当前仓储层只接受字符串，因而将合法结果误判为非法脚本结果，最终由 API 返回 `503 SERVICE_UNAVAILABLE`。

## 方案

保持 Upstash 自动反序列化、领取 Lua 脚本和 Redis 数据结构不变，仅调整领取结果解析边界：

- 字符串结果继续先执行 `JSON.parse`。
- 已反序列化的对象直接进入现有结构校验。
- 非字符串、非对象、未知状态或畸形载荷仍抛出 `Invalid claim script result`。

该兼容逻辑只作用于 `claimPost` 的返回值，不影响发布、大厅查询或 Redis 中的存量数据，因此无需清空线上测试数据。

## 测试

先新增单元测试，模拟 Upstash 返回已反序列化对象，并确认现有实现失败。完成最小修复后验证：

- 已反序列化的 `CLAIMED` 结果可正常返回载荷。
- 原有 JSON 字符串结果继续正常解析。
- 未知或畸形结果仍被拒绝。
- 单元测试、类型检查和生产构建全部通过。

## 部署

修复不涉及环境变量、数据库迁移或数据清理。提交并推送后由 Vercel 重新部署，再在线上发布一条测试记录并完成一次领取验证。
