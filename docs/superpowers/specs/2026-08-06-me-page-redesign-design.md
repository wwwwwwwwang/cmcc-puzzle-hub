# “我的”页面组重构设计

## 背景

当前“我的账户”页能够展示用户标识、信用余额、功能入口和信用流水，但信息层级偏弱，三个入口只是普通文本链接。`/me/posts`、`/me/claimed` 和 `/admin` 三个二级页也缺少返回上级页面的明确操作，空状态在移动端会产生较大的无信息留白。

本次重构参考首页和发布页已有的排版语言：白色页面背景、蓝色重点色、紧凑的移动端间距、清晰的标题层级和克制的边框。功能和数据规则保持不变，只优化信息架构、视觉层级、导航和状态呈现。

## 目标

- 将 `/me` 重构为紧凑的账户概览工作台。
- 强化信用余额、功能入口和信用流水之间的视觉层级。
- 为三个二级页提供统一、稳定的“返回我的账户”操作。
- 统一帖子列表、领取记录、审核列表和空状态的排版语言。
- 保持管理员功能的服务端权限边界，普通用户不显示也不能访问审核功能。
- 覆盖桌面窄容器和常见移动端视口，避免文字、按钮和长链接溢出。

## 非目标

- 不修改信用计算、信用流水原因或奖励规则。
- 不修改帖子、领取记录和待审核用户的查询逻辑。
- 不新增分页、筛选、搜索、复制按钮或统计接口。
- 不改变现有路由和底部主导航结构。
- 不改变非管理员访问 `/admin` 时返回 404 的行为。

## 方案选择

采用“概览工作台”方案。

该方案将信用作为账户页的核心信息，使用清晰的快捷入口连接“我的帖子”和“我领取的”；管理员额外获得“用户审核”入口。相比设置列表式，它能保留信用体系的产品重点；相比标签聚合式，它不会改变现有路由结构和用户心智。

## 页面结构

### 我的账户 `/me`

页面按以下顺序组织：

1. 页面标题“我的账户”和公开用户标识。
2. 信用概览区，展示当前信用和简短的获取、消耗规则。
3. 快捷入口区。
4. 最近信用流水。

普通用户看到两个等宽入口：

- 我的帖子：管理自己发布的拼图和帖子状态。
- 我领取的：查看领取成功的口令或链接。

管理员额外看到“用户审核”入口。移动端不使用三列布局：前两个入口保持两列，“用户审核”单独占满一行，确保文字和触控区域充足。

### 二级页统一页头

`/me/posts`、`/me/claimed` 和 `/admin` 使用同一个二级页头组件：

- 左侧为 Lucide 左箭头图标按钮。
- 链接固定指向 `/me`，不依赖浏览器历史记录。
- 链接具有无障碍名称“返回我的账户”。
- 标题和说明文字与发布页保持相近的字号、行高和间距。

底部主导航继续保留，三个页面中的“我的”导航项保持选中状态。

### 我的帖子 `/me/posts`

- 每条帖子以独立列表项展示类型、折扣、拼图编号和状态。
- 信息主体与操作区保持清晰间距。
- 仅 `OPEN` 状态显示现有下架按钮。
- 不改变状态文本和下架逻辑。

### 我领取的 `/me/claimed`

- 每条领取记录展示类型、折扣和拼图编号。
- 口令和链接使用分区排版，长文本允许换行。
- 链接继续在新标签页打开。
- 不新增复制、分享或跳转逻辑。

### 用户审核 `/admin`

- 仅管理员在 `/me` 看到入口。
- 页面继续先执行服务端管理员校验；非管理员访问时保持 `notFound()`。
- 审核条目以用户名为主信息，IP 为辅助信息。
- 同 IP 多账号继续使用琥珀色风险提示。
- 通过与拒绝按钮保留现有服务端 Action 和处理中状态，并在窄屏上避免挤压用户名和提示文本。

## 共享组件

### 二级页头

提取一个仅负责页面层级导航的共享组件，接收标题和说明文本。组件固定返回 `/me`，不承担权限判断或数据加载。

### 空状态

提取统一空状态组件，接收图标、标题和说明文本。三个二级页分别使用与场景对应的 Lucide 图标和文案：

- 我的帖子：尚未发布拼图。
- 我领取的：尚未领取拼图。
- 用户审核：暂无待审核用户。

空状态使用无额外业务操作的居中区域，减少大片空白，同时避免引入本次范围外的按钮和流程。

## 数据与权限

- `/me` 继续并行读取信用概览和会话信息。
- 管理员入口只根据服务端会话的 `isAdmin` 条件渲染。
- 普通用户页面中不渲染审核入口的 DOM。
- `/admin` 的服务端管理员校验继续作为最终权限边界。
- 未登录时 `/me` 保留登录提示，不展示账户工作台或管理入口。
- 查询结果为空时渲染空状态；现有查询抛出的错误继续交给 Next.js 错误边界处理，不在本次新增吞错逻辑。

## 视觉规则

- 页面水平内边距与发布页保持一致，主要使用 `px-4`。
- 标题、说明、分区标题沿用现有 Slate 色阶和蓝色重点色。
- 卡片圆角不超过现有设计体系，避免层层嵌套卡片。
- 快捷入口使用清晰图标、标题、说明和右向提示，整体作为可点击区域。
- 状态颜色只用于信用增减、帖子状态和审核风险，不扩大颜色种类。
- 固定触控区域尺寸，确保返回按钮、快捷入口和审核操作在移动端易于点击。

## 测试与验证

组件测试覆盖：

- `/me` 展示信用余额和两个普通用户入口。
- 普通用户不显示“用户审核”。
- 管理员显示“用户审核”。
- 三个二级页均显示指向 `/me` 的“返回我的账户”链接。
- 三个页面在空数据下显示对应空状态。
- 现有帖子下架和用户审核操作继续按条件出现。

完成后执行：

- 相关 Vitest 测试。
- 项目类型检查。
- 项目构建。
- 移动端和桌面窄容器的浏览器截图检查，确认内容不重叠、不溢出，底部导航不遮挡页面内容。
