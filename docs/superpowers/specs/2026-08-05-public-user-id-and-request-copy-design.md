# 公开用户标识与求助文案设计

## 目标

在大厅展示当前用户的稳定公开标识，并在最新发布帖子中展示发布者标识；同时让赠送和求助帖子使用符合语义的操作文案。

## 公开标识

服务端继续使用 FingerprintJS `visitorId` 做设备哈希。新增公开 ID 格式化函数，从 64 个十六进制字符（256 位）的 HMAC 中取前 16 个字符并大写，生成形如 `U-7A2F9C31E2AB4D07` 的标识。

该值不暴露原始 `visitorId` 或完整设备哈希，关闭并重新打开浏览器后保持稳定。公开 ID 仅用于界面识别，不参与领取权限判断。

新增 `POST /api/identity`：接收 `visitorId`，返回 `{ publicId }`。帖子 DTO 增加 `publisherId`，由服务端根据现有 `publisherDeviceHash` 计算，不修改 Redis 存储结构，也不需要迁移旧帖子。

## 前端展示

- `DeviceIdentityProvider` 在设备指纹准备完成后异步加载公开 ID。
- 身份接口失败时只显示“身份标识暂不可用”，不改变现有设备身份 `ready` 状态，不阻断发布和领取。
- 大厅标题下方显示“当前用户：U-…”；帖子元信息显示“发布者：U-…”。当发布者 ID 与当前用户 ID 相同时追加“（我）”。

## 求助文案

赠送帖使用“获取拼图”语义，求助帖使用“去助力”语义：

- 帖子卡片主按钮：`获取拼图` / `去助力`
- 抽屉标题：`领取` / `助力`
- 抽屉说明、确认提示、错误提示、进行中状态和方式按钮均按帖子类型切换

后端路由和 Redis 脚本继续使用 `claim` 名称，避免改变业务协议。

## 测试

- 公开 ID 格式稳定、长度固定，原始指纹不出现在响应中。
- 身份接口校验非法输入并返回公开 ID。
- 帖子 DTO 包含发布者 ID，旧帖子仍可正常转换。
- Provider 能展示身份加载、成功和失败状态，失败不影响设备身份 ready。
- PostCard 和 ClaimDrawer 分别覆盖 GIVE/REQUEST 的按钮、标题、说明和进行中文案。
