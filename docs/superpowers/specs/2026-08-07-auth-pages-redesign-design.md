# 登录与注册页 UI 重构设计

## 背景

登录和注册页目前沿用简单的页面流式布局，与首页、发布页和“我的”页已经形成的浅灰背景、白色内容区、蓝色主操作和轻边框卡片语言不一致。本次只重构认证页面的视觉和信息层级，不改变字段、服务端 action、跳转参数或认证行为。

## 目标

- 让登录和注册页与首页、发布页、“我的”页使用统一的配色、间距、圆角和卡片层级。
- 保持认证流程与现有无障碍语义，包括字段错误、服务端错误、处理中状态和 `redirect` 参数传递。
- 在桌面和移动端都提供稳定的窄内容区，避免认证表单被装饰性内容挤压。

## 方案

采用居中单卡片结构：页面使用浅灰白底，内容区限制最大宽度并在移动端保留 16px 内边距。卡片使用白色背景、浅色边框和轻阴影，圆角保持在现有设计系统范围内。

页面分为三层：

1. 顶部品牌区：展示小型互助标识、页面标题和一行简短说明。
2. 表单卡片：用户名和密码纵向排列，标签、输入框与错误提示拥有固定间距；提交按钮使用蓝色主操作样式。
3. 底部切换区：登录页链接到注册页，注册页链接到登录页，并继续携带 `redirect` 参数。

注册页的审核与信用规则说明改为独立的浅蓝提示条，保持信息可见但不让长段落挤压表单。

## 交互与状态

- 提交时沿用当前“处理中…”文案并禁用按钮。
- 字段错误继续渲染在对应输入框下方，并保留 `aria-invalid`。
- 服务端错误继续在表单底部使用 `role="alert"` 展示。
- 不增加新的账户字段、校验规则、服务端调用或跳转规则。

## 测试

- 扩展登录页测试：标题、用户名和密码字段、提交按钮、注册链接、`redirect` 参数。
- 扩展注册页测试：标题、字段、审核信用提示、登录链接、`redirect` 参数。
- 保留现有认证组件和 action 测试，完成后运行认证相关单测、全量单测、类型检查、lint 和构建。

## 非目标

- 不调整首页、发布页或“我的”页的现有视觉。
- 不引入新图片、插画、渐变英雄区或第三方认证方式。
- 不修改数据库、环境变量或 Supabase 配置。
